# 0011. Persistence with jOOQ's type-safe DSL, no SQL strings

- **Date:** 2026-05-28 (repositories on jOOQ); 2026-06-16 (generated classes in `persistence.impl.scheme`)
- **Status:** Accepted

## Context

The repositories were built from command classes, one per operation and entity (`FetchProductsCmd`, `InsertProductRowCmd`, `CountPurchasesCmd`, ...), over a `BaseCommand`. Each assembled SQL text line by line (`SqlList`, `SqlKeywords`, hand-written table descriptors) and ran it through JDBI. A column rename was found only at run time, the same projection logic was repeated in every fetch command, and each entity needed five or more classes.

## Decision

Repositories (`*RepositoryImpl`, extending `BaseRepositoryImpl`) build their queries with **jOOQ's type-safe DSL**; there are no SQL strings and no command classes.

- **Generated classes** from the schema live in `br.com.wdc.store.persistence.impl.scheme` (`Tables`, `Sequences`, `tables.EnProduct`, ...) — named after the database schema, since jOOQ is only the generation technology. Record classes are not generated.
- **Mapping in code:** each repository declares a static `JsonQuery` with `JsonQueryBuilder` (`framework.jooq`): per field, the getter, the setter and the column. From it the repository selects `JSON_OBJECT(...)` with only the fields the projection asks for, reads the JSON straight into the entity, and reuses the same mapping in relation subqueries (`JsonChildQueryBuilder`), avoiding N+1. `JsonDialect` adapts the JSON functions per database (H2, PostgreSQL and others in `framework.jooq.dialect`).
- **Criteria** are translated once, in `CriterionTranslator`; each entity's inner `ApplyConditions` only maps field → column ([0012](0012-criteria-are-fields-of-criterion.md)).
- **The `DSLContext`** comes from the app's holder `StoreDSLContext.BEAN` (`persistence.impl`) through `dsl()`; `framework.jooq` receives it by injection (`JsonQueryBuilder.setDSLContextSupplier`) and knows no application.

## Consequences

- A schema change breaks the compilation of the queries that use it, not a run.
- One repository class per entity, declarative, with no connection or transaction code ([0009](0009-programmatic-transactions-per-module.md)).
- The generated classes are checked in and regenerated by hand when the schema changes (`GenerateJooqSchema`, in the `scripts` module).
- The JDBI dependency outlived the migration and was removed on 2026-09-10.

## Alternatives considered

- **Command classes assembling SQL text over JDBI.** Replaced, for the reasons above.
